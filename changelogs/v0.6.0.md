# v0.6.0 — Hub for agents, input from the Hub, code orchestration

Preview release. Workflow version remains `3`. Changes since [v0.5.0](v0.5.0.md).

## Hub CLI for agents

- `agentflow hub overview | runs | run | workflows | machines | steps` print everything the Hub's pages show as JSON (`--format ndjson` for one line per item, a short table on a terminal), so an agent can analyse runs across machines. `hub run <machine>/<run-id>` (or a bare run id) has every step's timings, errors, summary, log tails, result and files, the graph, the machine, the steps waiting for input with their `output_schema`, and the commands sent to the run.
- `agentflow hub steps [--workflow W] [--days N]` ranks each workflow's steps by failures, with failure rate, retries, p50/p95, wait time and the most common errors (each with the latest run that hit it and its last stderr line).
- `agentflow hub submit <machine>/<run-id> <node> --output '{...}' [--wait]` answers a waiting step through the Hub after checking the step waits, its machine accepts commands, and the output satisfies `output_schema`; `--wait` waits until the machine applies or refuses it.
- Reads use `AGENTFLOW_HUB_VIEW_TOKEN` (or `view_token` in `~/.agentflow/hub.json`), else the ingest token; `--hub` overrides the address. A workspace `hub.json` cannot send your tokens to an address it chose.
- API: the run detail adds `graph`, `machine_info`, `waiting_inputs` and `commands`; `GET /api/v1/runs?run=` finds a run by id; machines list `capabilities`; new `GET /api/v1/steps`.

## Hub

- Submit input to a step waiting for it from the run page. The form is built from the node's `outputSchema`. Runners that opt in (`"accept_commands": true` in `~/.agentflow/hub.json` or `AGENTFLOW_HUB_ACCEPT_COMMANDS=1`, never from a workspace file) pull the submission while reporting, check it against their own state (same wait, schema) and hand it to the run's executor like `run submit`, then report applied or rejected. Forms carry a CSRF token and cross-site posts are refused.
- Each step's latest attempt reports the end of its stdout/stderr, a preview of its result JSON, and its files by name and size, masked and within a 32 KB budget per report (failed and running steps first). The run page shows them under each step; failed steps open by default.
- Finished runs older than `--retain` (default 90 days, `AGENTFLOW_HUB_RETAIN`, `0` keeps them forever) are removed at start and hourly, with the graphs no remaining run uses. Runs still going or waiting for input are always kept.
- SQLite migration 3 adds the `commands` table and machine capabilities; it runs on start.

## Code orchestration

- `agentflow code run <name> -- <script>` records a script as a run whose steps it drives. Inside it, `agentflow code step <id> [-- command]` records a step (run like an executor: result file, logs, exit code; or work the script did, with `--output`/`--summary`), and `code end` or the script's exit code ends it. Code runs live in `runs/` like workflow runs (workflow version `code`), show in `run list/get`, report to the Hub as `orchestration: code`, and draw their graph in the order the script reached steps, parallel steps included.
