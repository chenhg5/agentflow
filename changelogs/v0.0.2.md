## v0.0.2 — 2026-10-13

Second public preview of AgentFlow, focused on durable external triggers and reliable structured data contracts between workflow nodes.

### Highlights

- Added modular cron and webhook trigger sources with a persistent scheduler, HTTP intake server, durable dispatch queue, delivery receipts, and idempotency handling.
- Added trigger payload bindings from JSON payloads, headers, and attributes into workflow inputs.
- Added node `inputFields`, `outputFields`, and `inputMapping` for explicit and automatic field handoff across dependency edges.
- Replaced the local contract subset with JSON Schema Draft 2020-12 validation for workflow load and node execution.
- Persisted rendered node inputs as run artifacts for audit and replay inspection.
- Added stricter human approval output validation and result artifacts.
- Added deterministic CLI end-to-end coverage for contracts, dependencies, approvals, cron, webhook delivery, scheduler execution, and idempotency.
- Expanded the workflow schema, AgentFlow skill, installation guide, examples, and testing documentation.

### Install

```bash
go install github.com/chenhg5/agentflow/cmd/agentflow@v0.0.2
```

Or download the platform archive from the GitHub release and run `agentflow version`.

### Known limitations

- The web UI currently loads React Flow dependencies from public CDNs, so the browser needs network access to load the graph UI.
- Drivers are command templates rather than native vendor SDK integrations; provider command syntax must match the installed CLI.
- A single run advances nodes in the runner process; independent runs can run concurrently, but sharing one external agent session concurrently may conflict.
