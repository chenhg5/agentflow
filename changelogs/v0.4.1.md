# v0.4.1 — Durable queue and run relationships

Preview release. Workflow version remains `3`; this release adds generic runtime
admission and metadata without adding business-specific graph semantics.

## Windows checkpoint correction

The v0.4.0 candidate was not published after its Windows CI found readers could
block atomic state replacement. Store readers now open with delete sharing;
checkpoint replacement uses handle-based FileRenameInfoEx with POSIX replacement
semantics and retries bounded Windows sharing conflicts from
external readers or filesystem scanners. Tests hold an observer across multiple
atomic checkpoints, cover Unicode path lengths, and verify recovery after a non-sharing reader closes. The
existing 32-process idempotent CLI stress case remains part of the CI gate.
The v0.4.0 tag is retained unchanged because Go module versions are immutable.

## Durable execution

- Add `run enqueue`, `run worker --concurrency N`, and `run queue`. Enqueue commits
  the graph snapshot, inputs, run, creation journal and execution outbox before
  returning. Producers can exit without keeping child processes alive.
- Share one workspace admission owner across CLI starts, cron/webhooks, submit,
  retry, resume and cancel. Trigger serve attaches to an existing worker rather
  than allocating a second concurrency budget. Duplicate workers conflict.
- Preserve synchronous CLI behavior outside managed mode using the same queue.
  Enqueue, `--async`, or a persistent service enables durable managed mode;
  subsequent commands return acceptance, including while the worker is offline.
- Persist wake generations, claims and acknowledgements. Recover orphaned running
  work, interrupted creation, and control publication before its wake. A wake
  arriving during completion cannot be overwritten. Graceful shutdown drains
  active executions while retaining ownership.
- Release admission for runs waiting only on external input; mixed executing and
  waiting runs retain their slot. Expose counts, reasons, errors, owner and
  heartbeat in queue diagnostics.
- Make idempotent creation atomic across CLI/trigger processes. Changed requests
  under the same key return CLI exit 5 or webhook HTTP 409.

## Relationships and environments

- Add immutable same-workspace parent run, source node and opaque string
  correlation metadata, included in request identity. Parent/child state remains
  independent and cancellation does not cascade.
- Add parent/correlation list filters, direct child counts and Web navigation in
  both directions. Provider sessions remain a separate executor policy.
- Add executor environment modes `inherit` (default), `allowlist`, and `empty`
  across native/custom executors, sessions, retry and fallback. Preserve fresh
  engine I/O channels; diagnostics expose policy and variable names, not values.
- Clarify workspace layout: one root `workflow.json`, or all graph definitions
  under `workflows/` for a multi-graph workspace, without a duplicate root graph. Ignore generated queue/worker state in workspace Git scaffolds.
  Update authoring skill to 3.6.0 and document queue operation and recovery.

## Operational changes and boundaries

Managed commands confirm **durable acceptance**, not completion. Inspect the run
and its dispatch record for execution results. Concurrency limits active **runs**;
a run can still launch several parallel executors. Global executor quotas and
repository/session resource claims are not included.

Stop old workers before upgrading. This version does not migrate old trigger
queue records that lack the new generation protocol. Retain old run evidence in
its original workspace and use a fresh runtime store/workspace for queued work;
do not delete committed run data to force re-execution. Existing version 3 graph
and executor definitions remain usable; parent metadata is optional.

An interrupted, unacknowledged attempt may replay; programs must make external
side effects idempotent. Hard-killing a worker can leave external child processes
alive. Cancellation is processed at executor boundaries. Environment policies do
not isolate files, provider configuration or same-user processes.

The two static validator limitations documented in v0.3.0 remain: mixed source
session protocols and conditional fixed-session revisits can misclassify external
waiting fallbacks and parallel result availability. Exercise intended runtime
paths; these issues are tracked separately.

## Verification

Local gates: `make check`, `make test-e2e`, `make test-benchmark`, runtime race
checks, Web component checks and 11 simulated-transport adapter tests. The durable
queue suite uses actual CLI/worker/trigger/Web processes and deterministic Python
executors with external-input fixtures: 24 checks cover ten nonempty children,
4 active / 6 queued, waiting-slot release, concurrent submits, duplicate ownership,
queued cancellation, restarts, checkpoint retention, dispatcher retry and tracing.
These fixtures do not call model providers or send IM messages.
