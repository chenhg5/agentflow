# v0.5.0 — Hub, shared resources and durable review forms

Preview release. Workflow version remains `3`. Changes since [v0.4.1](v0.4.1.md).

## Hub

- `agentflow hub serve` collects runs from every machine into one web console (overview with a daily runs chart, runs with filters, run detail with a step timeline, workflows with P50/P95, machines) and a read API under `/api/v1`. Storage is SQLite through a pure-Go driver, so the binary stays cgo-free. The default port is `7075`. See [`docs/hub.md`](../docs/hub.md).
- Run reporting: with `AGENTFLOW_HUB_URL` (or `hub.json` in the workspace, or `~/.agentflow/hub.json`) set, commands that change runs report every state change, including newly created and queued runs, through `hub-outbox/` in the workspace. Reports are idempotent snapshots; secrets are masked before they leave the machine; a Hub outage never slows or fails a run.
- `agentflow hub push [--all]` delivers pending reports and backfills existing runs; `agentflow hub status` shows the configuration, outbox size and last delivery.
- The reporting protocol (`internal/hubapi`, version 1) carries `orchestration: json|code`, so a code-orchestrated runner can report to the same Hub.

## Runtime

- Preserve source protocol/no-session alternatives within activation routes; account for conditional fixed-session revisit fallbacks and external waiting in parallel result analysis. Separate join/dominator completion from prior-wave inference. Add structured conditional/unavailable/container-order diagnostics and deterministic session/runtime parity fixtures; static validation still does not verify real execution.

- Stable planned/received event bindings and latest-only fire-once catch-up, durable cron plans/cursors and prepared creation receipts, explicit enable/edit boundaries, skipped-range and delivery diagnostics via trigger status.

- Independent Feishu adapter: named text/multiline forms, immutable fixed-output mapping, actual merged-output validation, persisted selection/deadline arbitration, explicit timeout outputs, optional read-only pre-submit hook, rejection audit and separate acceptance/completion feedback. Deterministic transport/clock tests cover restart and stale-card boundaries; real user callbacks remain separate channel acceptance.

- Add same-store resource capacities and atomic per-attempt requests across runs and graph parallelism, resource waiting/readmission, orphan quarantine and explicit verified cleanup, CLI diagnostics and contract tests.

## CI and release

- Go files keep LF on Windows checkouts, and jobs run with `CGO_ENABLED=0` as releases are built (fixes `dyld: missing LC_UUID` on current macOS runners).
- Pushing a `v*` tag now builds the archives and publishes the GitHub release (`.github/workflows/release.yml`).
