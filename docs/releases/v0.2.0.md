# v0.2.0 — Standalone workflow workspaces

## Workspace layout v1

- Keep orchestration in a standalone directory: root `workflow.json`,
  `executors.json`, optional `triggers.json`, and generated `runs/`.
- Group owned agents under `executors/agents/` and programs under
  `executors/programs/`. Existing directories and symlinks can be registered
  without copying or modifying their contents.
- Add `workspace init`, `workspace validate`, `executor init`, `executor add`
  and machine-readable `schema workspace`.
- Codex scaffolding includes persistent role instructions, a skill, local MCP
  configuration and a read-only JSON input tool. Global Codex configuration is
  not modified.
- Distinguish `AGENTFLOW_ROOT` from `AGENTFLOW_WORKSPACE`; engine evidence stays
  at the workflow root even when executors work in other directories.

## Upgrade

This release changes workspace paths. Place executor and trigger configuration
at the workspace root and invoke commands there. The old hidden `.agentflow/`
layout and implicit home-directory executor registry are no longer read. Single
graphs can use root `workflow.json`; `workflows/` is optional for multiple graphs.
Graph format remains version 3; layout conventions are version 1.

## Scheduler and runtime fixes

- One trigger service per workspace, with OS locks against duplicate services
  and serialized cross-process delivery transactions.
- Delivery deduplication is scoped by trigger and delivery ID. Duplicate webhook
  paths are rejected. Webhook ports are reserved before starting work; cron-only
  services need no HTTP listener.
- Run listing and idempotency scans ignore unrelated directories while still
  reporting incomplete or corrupt runs.
- Relative executable availability checks resolve inside the executor workspace.

## Authoring and verification

- Updated skill, schemas, documentation and a standalone Codex workspace demo.
- New workspace authoring goldens and negative mutations, plus equivalent graph
  representations accepted by the existing benchmark.
- Grading checks rendered config and actual data, rather than requiring literal
  template syntax or a fixed instruction location.
- Migration guidance preserves source routing errors, defaults, normalization
  and loop limits instead of inventing successful exits.
- Local verification covered fresh-context authoring, real Codex/MCP runs,
  native parallel nodes, persistent human input and an actual cron occurrence.

External GitHub/CI/document services, production identities and notification
channels require their own executor configuration. Static workspace validation
reports `execution_verified:false`; use representative smoke runs to check
program and model behavior.

## Downloads

Archives include the binary, schemas, skill, examples, docs, scripts and authoring
benchmarks. Resources are packaged from the committed Git snapshot, excluding
local run evidence and ignored files. Targets: macOS, Linux and Windows, each on
amd64 and arm64. Verify downloads using `checksums.txt`.
